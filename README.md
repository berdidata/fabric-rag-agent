# Fabric RAG Agent

Ask questions over internal Markdown and PDF documents. Answers are generated by an Azure OpenAI model and cite the source chunks.

## Architecture

```
 Lakehouse /Files/docs (md, pdf)
          |
          v
 Fabric Notebook (01_ingest.py)
   - read + extract text
   - chunk (with overlap)
   - embed (Azure OpenAI text-embedding-3-small)
   - save chunks to Delta table (lineage, reruns)
   - push to Azure AI Search index (vector + keyword)
          |
          v
 Streamlit app (app/app.py)
   - agent with one tool: search_docs
   - model decides when/what to search
   - answer with [1], [2] citations
```

## Why Azure AI Search and not a Fabric-native vector store

Default choice: Azure AI Search. It gives hybrid search (vector + keyword), semantic ranking and a clean Python SDK, and the app does not need Fabric capacity running to answer questions.

Alternative if you want everything inside Fabric: a SQL database in Fabric with a `VECTOR` column and `VECTOR_DISTANCE()`. Better story for a "Fabric only" demo, weaker search quality out of the box (no hybrid, no semantic reranker). Pick one and say why in interviews; that trade-off is the interesting part of the project.

## Prerequisites

| Item | Notes |
|---|---|
| Fabric workspace with a Lakehouse | Trial capacity is fine |
| Azure OpenAI resource (or Foundry project) | Deploy `gpt-4o-mini` (chat) and `text-embedding-3-small` (embeddings) |
| Azure AI Search | Free tier works for a demo (check current limits) |
| Python 3.11, Git, GitHub account | |

Check the current API versions and SDK versions in Microsoft Learn before you start; they change often.

## Step 1. Provision Azure resources

1. In the Azure portal (or ai.azure.com for Foundry), create the OpenAI resource and deploy the two models. Note the deployment names.
2. Create an Azure AI Search service. Note endpoint and admin key.
3. Copy `.env.example` to `.env` and fill it in. Never commit `.env`.

For production, replace keys with Managed Identity / Entra ID and store secrets in Azure Key Vault. Fabric notebooks can read Key Vault with `notebookutils.credentials.getSecret`.

## Step 2. Upload documents to the Lakehouse

Lakehouse > Files > New subfolder `docs` > Upload files. Put a few `.md` and `.pdf` files there (sample docs are in `sample_docs/`).

## Step 3. Run the ingestion notebook

1. Import `notebooks/01_ingest.py` into Fabric (paste cells into a new notebook) and attach your Lakehouse as default.
2. First cell installs `openai`, `azure-search-documents`, `pypdf`, `tiktoken`.
3. Set your secrets (Key Vault or cell parameters).
4. Run all. You get a Delta table `doc_chunks` and a populated search index `docs-index`.

What to understand in this step:
- **Chunking**: ~500 tokens with 80 overlap. Too small loses context, too big dilutes relevance. Try it and compare answers.
- **Chunk ID**: hash of file + position, so reruns upsert instead of duplicating.
- **Delta table**: keeps the chunks queryable in Fabric (you can report on coverage in Power BI).

## Step 4. Run the app locally

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app/app.py
```

What to understand:
- The agent loop: the model gets a `search_docs` tool. It can call it zero, one or several times (for example to reformulate a query), then answers.
- Grounding: the system prompt forces it to answer only from retrieved chunks and cite them, and to say when it does not know.

## Step 5. Push to GitHub

```bash
git init
git add .
git commit -m "Fabric RAG agent: ingestion notebook + Streamlit agent"
git branch -M main
git remote add origin https://github.com/<you>/fabric-rag-agent.git
git push -u origin main
```

Optional: connect the Fabric workspace to the repo (Workspace settings > Git integration) so the notebook is versioned from Fabric directly.

## Step 6. Make it portfolio-grade

- Add an evaluation set (`eval/questions.csv`: question, expected source) and measure hit rate of retrieval. This is what most demos skip.
- Deploy the app to Azure App Service or Container Apps.
- Add a screenshot and a short "design decisions" section to this README.
